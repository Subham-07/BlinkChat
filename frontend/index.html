How BlinkChat Works

Step 1

🔑 Generate Credentials

Pick Temporary or Saved mode. BlinkChat creates a unique 8-character room code and a strong password.

Step 2

📤 Share Privately

Show your friend the generic QR code or send them the link to the entry page along with your room code & password.

Step 3

💬 Chat in Real Time

Connect via secure WebSockets. Once both participants join, the room is locked. Exactly two people, no eavesdroppers.

Two Chat Modes

Temporary Chat

🕐 Ephemeral by Design

Messages are held purely in server RAM while the session is live.

  • Zero database persistence for message content
  • Automatically expires after 4 hours of creation
  • Closes after 30 minutes of complete inactivity
  • In-memory buffers wiped immediately upon room eviction
Saved Chat

💾 Recoverable Session

Messages are persisted securely in the database so you can resume after closing a tab.

  • Messages persisted in SQLite database
  • Survives accidental browser refreshes and tab closes
  • Re-authenticate using the same room code and password
  • Retained for up to 7 days before automated cleanup

The Connection Flow

[ Creator ]

──Shares Offline──▶
[ Participant 2 ]
──POST /api/rooms/join──▶
[ 2-Person Room Locked ]
◀═══WebSocket Live Chat═══▶

🔒 Honest Privacy Disclosure

BlinkChat uses cryptographic password hashing (Argon2id), HttpOnly session cookies, and strict origin checks. In Temporary Mode, message texts are stored in application memory only and never written to disk. Note: this application does not implement end-to-end client encryption (E2EE); the server processes message payloads. It is designed for low-friction, private ad-hoc conversations between two individuals.
